# Fiche TP1 — Premier déploiement Kubernetes

## Concepts clés
- **Pod** : plus petite unité déployable, un ou plusieurs conteneurs qui partagent réseau/stockage
- **Deployment** : gère un ReplicaSet, garantit N replicas, pilote les rolling updates
- **Service** : `ClusterIP` (interne), `NodePort` (exposé sur chaque nœud), `LoadBalancer` (IP externe via le cloud provider)
- Rolling update / rollback, scaling manuel

## Commandes essentielles
```bash
kubectl create deployment <nom> --image=<image> --replicas=3
kubectl get pods -o wide
kubectl describe pod <pod>
kubectl logs <pod> -f
kubectl exec -it <pod> -- sh
kubectl expose deployment <nom> --type=NodePort --port=80
kubectl scale deployment <nom> --replicas=5
kubectl set image deployment/<nom> <conteneur>=<image>:<tag>
kubectl rollout status deployment/<nom>
kubectl rollout undo deployment/<nom>
```

## ⚠️ Pièges fréquents
- **Image non pinnée** (`nginx:latest`) : le contenu de `latest` change dans le temps, un déploiement reproductible aujourd'hui peut casser demain. Toujours épingler une version.
- **Secret en clair dans un manifest** (`value: "motdepasse"`) : jamais acceptable, même en TP — utiliser un `Secret` + `secretKeyRef`, dès le premier exercice.
- **`kubectl create deployment <nom>`** étiquette automatiquement les pods `app=<nom>` : un Service qui sélectionne un autre label (ex. `app: database` pour un deployment nommé `db`) ne matchera **aucun** pod.

## ✅ À retenir
Avant de chercher plus loin sur un problème de connectivité, toujours vérifier `kubectl get endpoints <service>` — vide, c'est presque toujours un mismatch de labels entre le `selector` du Service et les `labels` du Pod.
