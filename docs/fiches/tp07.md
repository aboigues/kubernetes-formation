# Fiche TP7 — Migration Docker Compose vers Kubernetes

## Concepts clés
- Correspondance des concepts : `service` → Deployment + Service, `depends_on` → initContainer, `volumes` → PVC, `environment` → ConfigMap/Secret
- **Kompose** : conversion automatique d'un `docker-compose.yml` (point de départ, pas une solution finale)
- Health checks explicites (Docker Compose n'en a pas d'équivalent aussi riche que les probes K8s)

## Commandes essentielles
```bash
kompose convert -f docker-compose.yml
kubectl apply -f kubernetes-manifests/
kubectl logs -l app=backend --tail=50
```

## ⚠️ Pièges fréquents
- `depends_on` dans Docker Compose ne garantit **que l'ordre de démarrage**, jamais que le service dépendant est réellement prêt à répondre. En Kubernetes, il faut un **initContainer** qui attend activement (`nc -z host port`, appel HTTP santé) avant de laisser démarrer le conteneur principal.
- La sécurité n'est **pas portée automatiquement** par la migration : Docker Compose ne force rien niveau `securityContext`, resources limits ou moindre privilège. Migrer un `docker-compose.yml` "tel quel" reproduit son absence de durcissement — c'est le moment de l'ajouter, pas de le reporter.
- Les chemins relatifs de volumes changent de sens selon l'endroit où vit le fichier `docker-compose.yml` — vérifier systématiquement à quoi ils pointent réellement une fois le fichier déplacé.

## ✅ À retenir
Une migration réussie n'est pas "faire pareil sur un autre orchestrateur" : c'est l'occasion d'ajouter ce que Docker Compose ne permettait pas nativement (health checks fiables, limites de ressources, moindre privilège).
